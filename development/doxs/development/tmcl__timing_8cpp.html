Detailed Description

Measures the cost of one TMCL parameter access over SPI: single vs pipelined, across frame-gap settings, with a latency histogram per configuration.

What it does (chip in parameter mode, motor control idle; nothing moves):

  1. Writes known patterns into global bank-2 user variables 0..7 so every read can be checked against an expected value (detects stale or shifted replies).
  2. For each timing profile (legacy 1000 us gap, then a gap sweep down to 0 us with NOT_READY polling) runs single GGP reads and reports min / p50 / p99 / max, a histogram, NOT_READY / stale / failure counts and value mismatches.
  3. Runs pipelined batches of 6 and 8 reads (readGlobalParameters) with the same profiles and reports per-batch and per-element time.
  4. Reads G0:12 MAIN_LOOPS so the result can be related to the firmware main-loop rate.

Timing uses esp_timer_get_time() (1 us resolution) around each access. Build with ./scripts/build_app.sh tmcl_timing Release and flash as for the other examples. Results are printed on the console; copy them into the driver's "Timing and throughput" docs section when they replace the derived numbers there.

Board wiring and SPI clock come from Esp32Tmc9660BusConfig (esp32_tmc9660_bus.hpp); change kSpiClockHz below to measure at another clock (the TMC9660 accepts up to 10 MHz).
